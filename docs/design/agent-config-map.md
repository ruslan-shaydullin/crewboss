# AgentConfigMap — декларативный control-plane для агентов (design, milestone #354)

## Идея в одну фразу
Дерево **team** становится декларативным source-of-truth (как набор K8s-манифестов): каждая
**роль = Deployment** (capabilities + replicas), **лаунчер = reconciler**, **спавн = pod**.
Один базовый образ агента поднимается в любую роль ровно с заявленными правами — и права
**enforced песочницей физически** (nsjail/FS/seccomp/net/creds), а не обещаны в промпте.
Цель: 100+ ролей = конфиги в дереве, а не ветки-костыли в спавнере.

## K8s → crewboss (маппинг)
| K8s | crewboss | Сейчас |
|---|---|---|
| Cluster | бокс `cbnet` | ✅ |
| Namespace | команда/орг (`team-selfbuild/`) | ✅ дерево team |
| Container image | базовый образ агента (claude + nsjail) | ✅ один на всех |
| Deployment | спек роли в дереве team (capabilities + replicas) | ⚠️ только `tools:` frontmatter |
| PodSpec/securityContext | капабилити-спек (fs/net/creds/seccomp) | ❌ строим |
| replicas | пер-ролевой потолок параллелизма | ⚠️ глобальный `CB_MAX_PARALLEL` |
| Pod | один nsjail'd агент | ✅ `crewboss-spawn.sh` |
| Scheduler/reconciler | лаунчер-петля | ✅ work-driven |
| `kubectl describe` | интроспекция роли (тех + юзер вид) | ❌ строим |

Это **эволюция существующих кусков**, не greenfield.

## Текущее состояние (заземлено в коде) — что enforced, что нет
Спавн: `reference/runtime/crewboss-spawn.sh` → один `nsjail` (стр.77–85), один seccomp
`claude.kafel` **на все роли**.
- **Физически есть, но НЕ по ролям:** ФС вне `/work`+`/cbnet` read-only (`-R …`); сеть через
  прокси-allowlist (`HTTPS_PROXY=127.0.0.1:3128`→`proxy.py`); seccomp; `GH_TOKEN` только при `PR_REPO`.
- **Дыра:** `-B "$WORK:/work"` (стр.81) — рабочий каталог **read-WRITE для ВСЕХ, включая аналитика**.
  «Read-only роль» держит только `claude --agent` (список инструментов) + хук-гейт = **friction**,
  протекает на `${IFS}`/`eval`. Аналитик с `Bash` физически МОЖЕТ писать в код. Это и чиним.

## Принцип: default-deny, спек только ДОБАВЛЯЕТ
Старт от нуля прав; capability-секция = allow-list. Нет секции = **сегодняшнее поведение**
(`fs.work: rw`, общий профиль) → нулевая регрессия для немигрированных ролей. Кривой конфиг =
ноль прав (fail-safe), не полный доступ.

## Словарь capabilities → enforcement
| Capability | Спек | Enforcement в спавнере |
|---|---|---|
| `fs.work` | `ro`/`rw` | `-R` vs `-B "$WORK:/work"` |
| `fs.extra` | пути ro/rw | доп. `-R`/`-B` |
| `net` | `none`/`board`/`git`/`open` | пер-ролевые правила прокси |
| `creds` | `none`/`board`/`git-write` | условный `--env GH_TOKEN` / git-helper |
| `tools` | список | `claude --agent` allow-list (вторичный, friction) |
| `seccomp` | имя профиля | пер-роль `.kafel` (позже; общий базовый пока) |
| `spawn` | bool | разрешение поднимать суб-агентов |
| `replicas` | N | пер-ролевой семафор параллелизма (см. ниже) |

## Модель реплик (важно — отличается от K8s)
`replicas: N` = **до N инстансов роли одновременно, каждый на СВОЕЙ задаче**. Это **потолок**,
а НЕ «держать N живыми» — агенты остаются эфемерными/work-driven; дерево объявляет конверт
(права + макс. параллелизм), работа борда триггерит спавны внутри конверта. Так desired-state
(дерево) и work-driven (борд) женятся без тёплого пула.

**Инвариант:** одна роль × одна задача = максимум ОДИН агент. Никакого ансамбля на одну задачу
(два аналитика на один чартер — запрещено). Разные роли параллельно — без этого ограничения.

Реализация в лаунчере (почти даром): уникальность (роль×задача) уже даёт pid-guard; новое —
пер-ролевой семафор из дерева вместо глобального `CB_MAX_PARALLEL`. Перед спавном R на T:
есть R на T? → пропуск; крутится `replicas(R)` инстансов R на других задачах? → отложить; иначе спавн.

## Reconciler
Лаунчер читает дерево team как **desired-state**: для каждой роли — capabilities (конверт прав)
+ replicas (потолок). Сводит desired с actual (что реально крутится), оставаясь триггерным от
борда. Спавн всегда внутри заявленного конверта.

## Интроспекция роли — два вида
- **Технический:** raw-спек роли (`describe`-стиль: capabilities, replicas, nsjail-флаги, seccomp).
- **Пользовательский:** человекочитаемая карточка в дашборде :8787 («Аналитик: read-only, читает код
  + пишет в борд, не пишет/не мержит, до 2 инстансов»).
Оба — из одного канонического спека в дереве team.

## Верификация (иначе «физически enforced» = обещание)
Каждый барьер — **адверсариальный тест**: поднять роль в её песочнице → заставить ПОПРОБОВАТЬ
нарушить (записать в `/work`, запушить, `curl` мимо прокси, превысить replicas) → **assert не смог**
(EROFS/exit≠0/семафор держит). Без зелёного — миграция роли не сделана. Паттерн как Layer-A/B харнессы.

## AgentConfigMap vs хук-гейт
Физбарьер (песочница из спека) — **первичный**. Хук-гейт (`crewboss-gate.sh`) → **аудит/вторая
стенка** (лог + тонкие внутри-инструментные различия типа `gh issue` vs `gh pr merge`). Так
перестаём over-claim'ить «enforced» там, где раньше была только friction.

## Фазы (milestone #354)
1. **P1 — физбарьер (PoC):** capability-секция в дереве team + `provision()` в `crewboss-spawn.sh`
   (`-R` vs `-B` для `/work`) → `fs.work: ro` для `solution-analyst` + `reviewer`. Адверсариальный
   тест. Default-deny back-compat. **Операторски** (bootstrap: песочница не строит себя через
   ограничиваемых ею агентов).
2. **P2 — полный словарь capabilities:** creds/net/seccomp per-role.
3. **P3 — per-role replicas:** семафор из дерева, инвариант роль×задача.
4. **P4 — reconciler:** лаунчер читает дерево как desired-state.
5. **P5 — интроспекция:** технический + пользовательский вид роли (дашборд).
6. **P6 — раскатка:** на все роли (cto/managers code-blind → executors rw+scoped).

## Решено (было «открытым»)
- Capabilities живут **в дереве team** (часть спека роли), не отдельный файл.
- Это **milestone**, не чартер.
- Физбарьер первичен, гейт — аудит.
- Реплики = **потолок параллелизма**, инвариант одна-роль-одна-задача.
