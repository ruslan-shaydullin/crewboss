(меняют только исполнители под человеческим аппрувом).

## Принципы (3 свойства на каждом трансформе)
1. Правильный размер (milestone/charter/leaf; ловить дедлок- и матрёшка-нарезку).
2. Сходимость вместо переброса (роли итерируют до согласия, с лимитом раундов → эскалация к человеку).
3. Верность исходному намерению (базовый промпт юзера тащится сквозь всю цепочку).
Плюс: заземление о реальный код, планка-приёмки заранее, взгляд на очередь, сверка исхода, само-детект (не само-фикс).

## Очерёдность (C1 жёстко первым, остальное переставляемо)
- **C1 (#335) [ЯДРО]** — механизм сходимости анализ↔план + МЕХАНИЧЕСКИЙ (стаб) аналитик.
  Bootstrap (#193): отладить плумбинг (converge/bond/escalate/история) детерминированно, без шума модели.
  Бонд раундов → эскалация к человеку. Строится операторски/проверяемо (launcher-core).
- **C2 (#336)** — реальный generalist-аналитик в проверенный механизм (стаб → живой агент, механизм не меняется).
- **C3 (#337)** — якорь намерения: босс пишет базовый промпт юзера; intent-аналитик сверяет. Гейт на boss-чате #291.
- **C4 (#338)** — grounding-аналитик: реальный код, гочи (ловит повторные «не знал X»: #280, классификация теста).
- **C5 (#339)** — acceptance / test-planner (#184): «готово» = план тестов до работы.
- **C6 (#340)** — scoping / размерщик: charter↔milestone, атомарность листа.
- **C7 (#341)** — dependency / анализ очереди (умнее blast-radius-метки; #304/#190).
- **C8 (#342)** — наблюдатели: outcome после деплоя (#146) + loop/meta (детект повторов → человеку, не чинят).

## Ключевые решения
- C1 = механизм отдельно от интеллекта (механический стаб первым) — ответ на «как хорошо отработает».
- Сходимость с потолком раундов → человек (не бесконечный пинг-понг/слив денег).
- Все аналитики/наблюдатели read-only.
- Бутстрап-свойство: после C1+C2 чартеры C3–C8 уже планируются через новый анализ.
